# App Store screenshots — how they are made

How Leap's marketing screenshots are **composed, verified and uploaded**. The
whole set is generated by one script — nothing is hand-edited in an image
editor, and **no marketing pixel is ever retouched**.

- Generator: [`docs/store/screenshots/make_frames.py`](../store/screenshots/make_frames.py)
- Delivered set: `docs/store/screenshots/iphone-67/` (8 PNGs)
- Uploader: [`scripts/asc_screenshots.sh`](../../scripts/asc_screenshots.sh)
- Capture provenance + the full Premium-state audit:
  [`docs/store/screenshots/README.md`](../store/screenshots/README.md)
- Field limits / `screenshotDisplayType` enum:
  [app-store-listing.md](app-store-listing.md) §5

```sh
python3 docs/store/screenshots/make_frames.py          # rewrites iphone-67/
ASC_KEY_ID=... ASC_ISSUER_ID=... ./scripts/asc_screenshots.sh
```

---

## Invariants — do not break these

- **1290×2796, RGB, no alpha, square outer canvas corners, PNG.** This one set
  covers 6.7" *and* 6.9": the ASC API has **no `APP_IPHONE_69`** bucket. Verify
  with `sips -g pixelWidth -g pixelHeight -g hasAlpha`.
- **Every capture is from the app's PREMIUM (unlocked) state.** Owner's hard
  requirement: **no frame may show** the paywall, any upgrade / unlock / trial
  CTA, `Restore Purchases`, a price, a locked face (`LeapLockedFace`), a hit
  free-tier cap, or any debug UI.
- **No caption may say "transparent" / "see-through" / "clear" / "invisible".**
  Captions use the **"blends in"** framing that matches the live subtitle, and
  describe the *outcome*. Search keywords are handled in the ASC keywords field
  and are never displayed. This is deliberate 2.5.1 / rejection-risk reduction.
- **Every claim must be literally true and sourced from the running app.** Counts
  come from `LeapCatalogStats`. **No invented social proof** — no ratings,
  awards, user counts or "#1" badges (2.3.1 / 3.2.2(i)).
- **Never upscale a source render.** Every tile is placed at ≤ its native
  captured pixel size.
- **Never composite a widget onto a photo to fake host transparency.**
  Arranging *real* renders into a marketing composition is legitimate; faking
  the effect is not.
- **Raw captures live in `/tmp/shots` and are NOT committed.** If they are lost,
  the frames cannot be re-rendered without redoing the whole simulator capture
  session. This is the pipeline's single biggest fragility.

| 1 | `01-showcase.png` | showcase | Tilted Browse phone + **8 real square widget renders** scattered around it |
| 2 | `02-blend.png` | showcase, no phone | **6 real "blend" renders** with their wallpaper keyed out — content floating with no card |
| 3 | `03-home.png` | device | Home tab, upright in a titanium body |
| 4 | `04-browse.png` | device | Browse gallery ("3,500+ unique widgets" header) |
| 5 | `05-styles.png` | device | Edit-Widget sheet, one clock across all 4 styles |
| 6 | `06-streak.png` | device | Home, day-streak card (**18** / best **24**) |
| 7 | `07-library.png` | card | Saved-widget list, scrolled |
| 8 | `08-privacy.png` | card | Settings, cropped APPEARANCE → legal footer |

Frames are emitted in three passes by `main()`: `SHOWCASE` list →
`compose_showcase`, the `HOME` dict → `compose_home`, then the `MATTE` list →
`compose_matte`. **Output order is the App Store display order**, which
`asc_screenshots.sh` derives by sorting on filename — so the numeric prefixes
are load-bearing.

## The three treatments

**Showcase** (`compose_showcase`) — caption over a branded background, a
optionally tilted phone (`make_phone`), and a scatter of tiles pasted with
`paste_rotated`. Tile specs are `(file, cx, cy, width, angle[, trim])`.

**Device** (`compose_home`, and `compose_matte` when the entry's 8th element is
`True`) — the capture wrapped in `make_device`: a titanium body with a squircle
outer edge, a **concentric** screen (`screen_r = body_r - bezel`), a metal rim
highlight, side buttons and a drop shadow.

**Card** (`compose_matte` default path, via `rounded_shot`) — the capture
masked to a plain rounded inset with a hairline border and shadow.

### Which capture may wear a device body

**Only a capture that still has its real status bar and Dynamic Island.** A body
implies a whole phone; if the capture's top was cropped away, the top bezel sits
above content that starts mid-screen and it reads as a rendering glitch.

- `04-browse`, `05-styles`, `06-streak` → device (`crop_top = 0`).
- `07-library`, `08-privacy` → **card**, because their captures are scrolled or
  sliced.

`05-styles` originally used `crop_top=230` to drop the sheet's status bar; that
crop was **removed** when it gained a body, because the body needs that bar.

> ⛔️ **`08-privacy` must keep `crop_top=1095`.** The uncropped Settings capture
> predates the copy fix and still shows the retired **"Unlimited widgets
> Unlimited photos"** string on the Premium card, plus a `Restore Purchases`
> row. Widening that crop reintroduces a false claim *and* a purchase control.

## Corner geometry — the part that is easy to get wrong

Every rounded corner is a continuous **squircle** (superellipse),
`|dx/r|^n + |dy/r|^n ≤ 1`, built by `squircle_mask()` at **4× supersample then
LANCZOS** so the curve is clean rather than stair-stepped. A plain circular-arc
`rounded_rectangle` reads subtly wrong next to real Apple hardware.

Three module constants, all overridable by env var so a variant can be rendered
into a **separate folder** without disturbing the uploaded set:

| Constant | Env | Default | What |
|---|---|---|---|
| `BODY_R_RATIO` | `LEAP_BODY_R` | `0.152` | Phone body corner, as a fraction of body width. Screen corner is derived concentrically. |
| `CARD_R_RATIO` | `LEAP_CARD_R` | `0.14` | Plain rounded inset corner (card treatment). |
| `SQ_N` | `LEAP_SQ_N` | `4.8` | Superellipse exponent for bodies and cards. |
| `TILE_N` | — | `4.8` | **Pinned.** Widget-tile corner. |
| `OUT` | `LEAP_SHOT_OUT` | `iphone-67` | Output folder name under `docs/store/screenshots/`. |

The defaults reproduce the uploaded set exactly, so a bare run is always safe.

> ⚠️ **The exponent — not the radius — controls perceived roundness.** At
> `n = 4.8` the edge stays flat almost to the corner and then turns sharply,
> which reads *square* no matter how large the radius. Raising the body radius
> from `0.152` → `0.205` was **barely visible**. Lowering `n` is the knob that
> actually works. A rounder, more iPhone-like variant lives in
> `iphone-67-round/` at **body `0.215` / card `0.195` / `n = 2.8`**; `n ≈ 2.2`
> is already too circular and starts encroaching on the Dynamic Island.

> ⚠️ **`TILE_N` is pinned at 4.8 on purpose.** iOS's own widget corner is a
> *tight* squircle. When `SQ_N` was first lowered globally the floating widget
> tiles in frame 01 turned noticeably circular and stopped looking like iOS
> widgets. `make_tile` and `make_floating` must always pass `TILE_N`
> explicitly — to `squircle_mask` **and** to `squircle_shadow`.

**Concentric screen corners are the single most common tell of a fake mockup.**
Always zoom into a corner of a final PNG before shipping.

## Traps, each found the hard way

- **A design that bakes a coloured outer glow needs `trim`.** Gradient Battery /
  Neon renders extend past their own card corner, so *no* mask radius can follow
  both the capture bounds and the card corner — masking the raw capture leaves a
  **coral crescent**. `make_tile(trim=N)` crops N source pixels off every edge
  **before** masking, fixing it at the source. The defect is in the capture, not
  the mask; rounding the mask harder does not fix it.
- **`make_floating`'s luminance floor (`lo`) must clear the wallpaper.** The
  blend preview's "midnight" wallpaper is a dark **gradient**, not pure black.
  At `lo=40` the whole card stayed faintly keyed in and a **ghost rounded
  rectangle** appeared behind the content — literally the "card" that frame 02's
  headline says is not there. `lo=66` drops it.
- **The single background bloom is fully decayed by y≈1100.** Everything below
  is flat ink. That is right under a bright phone mockup, but a frame with no
  phone (02) or a short card (08) gets a **dead black region**. Pass
  `background(lower_bloom=True)` — a second dimmer bloom (r=900, cy=1900). In
  `compose_matte` this is keyed off `bool(crop_bottom)`.
- **A short crop must not be vertically centred.** It floats in the middle and
  leaves a dead band under the caption that reads as a layout mistake at
  thumbnail size. `compose_matte` biases to **0.34** of the free region.
- **A widened crop is usually a duplicate.** A "CLOCKS" frame was cut: its crop
  was ~850px of 2796 and rendered as a thin strip marooned in dead space, and
  widening it just reproduced the Browse frame. A redundant weak frame costs
  more than the slot is worth.
- **Two frames of the same screen must differ at thumbnail size.** `03-home` and
  `06-streak` are both the Home tab; they stay distinguishable only because
  their hero cards differ (black dot-matrix clock vs a large orange streak
  card). Check this whenever a treatment changes.
- **Captures can go stale against the shipped binary.** The set still reads
  "1 days left in Jul" because the captures predate the pluralization fix.
  Judged acceptable (trivial, not a misrepresentation) — and **retouching the
  pixels instead would violate the honesty rule**. Re-capturing means redoing
  the whole simulator session.
- **The date in a capture matters.** The Home raw is deliberately a **Jul 30**
  capture so the *Date Focus* tile reads "1 days left in Jul" and never a
  broken-looking "0 days".
- **Never show a weather face.** WeatherKit returns a deterministic placeholder
  unless it is actually serving data, so a weather frame would advertise fake
  data. See [weatherkit.md](weatherkit.md).

## Verification before upload

Do all of this yourself — **do not trust a sub-agent's ✅**. An agent passed all
frames once while four real defects were present.

1. `sips -g pixelWidth -g pixelHeight -g hasAlpha` on every PNG → 1290×2796, no.
2. **Open every frame** downscaled (≈⅓) to judge it at thumbnail size.
3. **Zoom into all four corners** of at least one device frame at full
   resolution — check the concentric screen corner, the bezel and the side rails.
4. Re-read the Premium-state checklist above against each frame.
5. `git status` — confirm nothing else changed.

Upload replaces the whole set unless `KEEP=1`. Read the **final table**: wrong
dimensions are *not* rejected at upload time, they surface later in
`assetDeliveryState.errors`. Then re-poll the set and confirm every entry is
`COMPLETE` with `[]` errors — `UPLOAD_COMPLETE` is not yet final.

```sh
.build/tools/asc_api GET "/v1/appScreenshotSets/<setId>/appScreenshots?limit=50"
```
